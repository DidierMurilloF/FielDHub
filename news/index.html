    Changelog¶

    FielDHub 1.7.6¶

    Spatial correlations drawn for each simulated trial¶

    • In stats::simulate(x, spatial = ...), rho_row and rho_col each take one fixed value or a range c(low, high). A range is drawn from uniformly for every draw and every location, so each location of each simulated trial has its own spatial field. A correlation that is not given is drawn from 0.15 to 0.9.
    • The true correlations of every draw and location are returned in the new spatial_draws table of the result (draw, LOCATION, rho_row, rho_col) and shown when the simulation is printed. reproduce_simulation() draws the same values again.
    • The drawn correlations depend only on the seed, nsim and the number of locations, so two layouts simulated with the same seed, even of different designs, share them.

    Changes to results and outputs¶

    • simulate(x, spatial = TRUE) now draws both correlations from 0.15 to 0.9 for each draw and location; in 1.7.5 it fixed them at 0.5. Give spatial = list(rho_row = 0.5, rho_col = 0.5) for the 1.7.5 values. Simulations with fixed correlations give the same values as in 1.7.5 for the same seed.
    • The Shiny app is unchanged: its Add spatial correlation option always uses the correlations selected in the dialog.

    FielDHub 1.7.5¶

    Design-aware trait simulation¶

    • stats::simulate(x) generates Gaussian trait data for all 21 field designs using their realized treatment and experimental units. Repeated entries and checks retain a shared treatment effect across locations. Set the trait mean and residual SD globally or by location. Spatial correlation is optional and uses physical field-book coordinates. Shiny calls the package method and uses its simulated field book for tables, maps, and downloads. reproduce_simulation() replays new and existing records.
    • Simulated augmented RCBD block effects are nested within experiment and location. In augmented RCBD, whose entry list may repeat a display label, distinct entries with the same label keep separate treatment effects. Row-column layouts preserve the experimental axes as ROW_REP and COLUMN_REP, so spatial simulation can use physical coordinates alongside the experimental units.
    • Each fieldhub_simulation now prints a short summary instead of every stored table. The simulated effects behind each draw remain in effects.
    • The new vignette “Simulating Trait Data on a Field Design” (vignette("simulating_traits")) shows how to simulate traits and use the known effects for teaching, planning and testing analyses.

    Changes to results and outputs¶

    Field designs and their randomization are unchanged for a given seed. The simulated values and one layout format change:

    • The Simulate! dialog now asks for the trait mean and plot-error (residual) SD instead of minimum and maximum values, and the app calls stats::simulate(). Simulated values differ from those of FielDHub 1.7.0 for the same seed, and are Gaussian, so they are no longer bounded by a minimum or maximum.
    • On the spatial pages (diagonal, optimized, partially replicated, multi-location p-rep, sparse, augmented RCBD and augmented row-column), spatial correlation is now optional. It is off unless Add spatial correlation is ticked; 1.7.0 always applied it.
    • Row-column field layouts, in the app and from field_layout(), have two additional columns, ROW_REP and COLUMN_REP, between REP and ENTRY.

    Simulation records saved with FielDHub 1.7.0 still replay with reproduce_simulation().

    Bug fixes¶

    • diagonal_arrangement() accepts checks given as the check entry numbers, for example checks = c(301, 302), as optimized_arrangement() does. It previously stopped with “the condition has length > 1”.
    • With a serpentine planter, the incomplete-block layouts that lay each incomplete block as a column of a replicate (stacked = "horizontal") now number the plots along the planter’s path: down the first block, back up the next, as the cartesian layout numbers them down every block. The plot numbers of these layouts change; the designs and the other layouts do not.

    FielDHub 1.7.0¶

    New design¶

    • augmented_row_column() generates augmented row-column designs: replicated checks and unreplicated test entries in a complete rectangular field, with every check appearing exactly once in every field line along a chosen check_direction (“columns” or “rows”) and every test entry appearing once. The check positions are chosen by a staged annealing search under one of three criteria: V_tt (the default; mean variance of test-versus-test comparisons), V_tc (test-versus-check) or E_aug (harmonic-mean efficiency of all treatment comparisons), with fixed row and column effects. The search is FielDHub’s own method, not part of the published construction. Several locations are supported, and the field book includes a CHECK_DIRECTION column. Fields with fewer than 10 residual degrees of freedom raise a warning. Results record the seed and replay exactly with reproduce_design() within the same environment (package and R versions, BLAS/LAPACK library and thread count, and platform).
    • The app has a new page, Augmented Row-Column, under Unreplicated Designs.
    • A new vignette, “Augmented Row-Column Design”, is added to the Articles menu.
    • The design arguments vocabulary gains entries: the test entries excluding checks, as a count or as a vector of labels (see help("design_arguments", package = "FielDHub")).
    • The construction follows Piepho and Williams (2026); the square-array foundation follows Bailey and Haines (2025). Existing designs are unchanged.

    Enhancements¶

    • Field dimensions for the classic designs. CRD(), RCBD(), latin_square(), full_factorial(), split_plot(), split_split_plot(), strip_plot(), incomplete_blocks(), alpha_lattice(), square_lattice() and rectangular_lattice() gain nrows and ncols, the rows and columns of the field at each location; field_layout() gains the same two arguments for a design built without them. One dimension is enough: the other follows from the number of plots. The units of the design (complete blocks, replicates and incomplete blocks, whole plots and subplots, Latin squares, strip grids) are equal rectangles of the field, and the plots are numbered along the planting path of the whole field, serpentine or cartesian, so that consecutive plot numbers of a serpentine are neighbours (whole plots of split and split-split plots follow the path over the grid of whole plots). The randomization is that of the same call without dimensions: only PLOT, ROW and COLUMN differ. Dimensions that do not fit are an error that suggests valid ones, and layout together with dimensions is an error. A design built with dimensions has that one layout: field_layout() returns it, and asking for another planter, another stacking or other dimensions is an error that says to build the design again with other dimensions or without them. plot() follows the same rules. See ?field_layout.

    • stacked arranges the replicates of a field of given dimensions, in the same eleven functions, in field_layout() and in plot(): "vertical" puts them one above another (each across all the columns of the field), "horizontal" side by side (each down all its rows) and "grid_panel" in rows and columns of replicates. The replicates are the complete blocks of an RCBD or of a factorial in blocks, the replicates of split, split-split and strip plots, of incomplete blocks and of the lattices, and the squares of a Latin square. Dimensions that do not fit the stacking are an error that suggests dimensions that do. When stacked is not given, the stacking is the one whose replicate is the most square among those that fit the dimensions (a 4 x 3 replicate rather than a 6 x 2 one); a tie goes to the vertical stack, then to the horizontal one, then to the panel with the most rows of replicates. The stacking chosen is recorded in metadata$parameters and in infoDesign, so print() shows it and reproduce_design() rebuilds the same field. A CRD, and a factorial or a split plot in CRD, has no replicates to stack: stacked with its dimensions is an error, and so is stacked without dimensions in a constructor.

    • RCBD() with dimensions keeps plotNumber as the matrix of blocks by plots and adds the field map of the plot numbers as plotNumberField. The plot-number tables of Latin squares, strip plots and split plots (plotSquares, plotLayouts, layoutlocations) carry the numbers of the grid. Every design built with dimensions records nrows and ncols in infoDesign, beside its stacking, so print() and summary() show the field of a lattice or a split plot as they show that of an RCBD.

    • In the app, the layout menu on the plot has the same names on every page. “Replicate layout” (before, “Reps layout”) offers “Vertical”, “Horizontal” and “Grid panel”; “Field dimensions” (before, “Layout option”) lists the fields, each named by its rows and columns (“6 × 9”): the numbered layouts (which are unchanged) first, then the field grids, each from the most square on, so every menu opens on the layout it opened on before. A menu lists only the fields whose replicates lie as it says, numbered layouts and field grids alike: “Vertical” those with the replicates one above another, “Horizontal” those with the replicates side by side (three blocks of 24 have their “1 × 72” field there), “Grid panel” those with rows and columns of replicates, more than one of each, as stacked = "grid_panel" of field_layout() has them. Every option of “Grid panel” says how its replicates lie (“6 × 12 · replicates 2 × 2”, rows by columns of replicates), and “Grid panel” is offered only to a design that has such a field: two or three replicates have none. Fields of one size say what tells them apart (“16 × 4 · blocks in rows”, “4 × 4 · whole plots in columns”) instead of a number, and a layout that was listed twice is listed once. Whole plots or blocks that wrap from one row of the field into the next say “whole plots along the path” or “blocks along the path”. A field grid of the size of a numbered layout is listed when its incomplete blocks or its whole plots lie another way, and both say how: four replicates of 16 treatments in blocks of 4 have “8 × 8 · replicates 2 × 2 · blocks in columns” (layout 1) and “8 × 8 · replicates 2 × 2 · blocks in rows” (the field of nrows = 8, ncols = 8) under “Grid panel”. A grid with the same field as a numbered layout, or with another path of the plots inside the replicate only, is not listed again. A design without replicates to arrange (a CRD, a factorial or a split plot in a CRD, a single Latin square) has one list of fields, its field grids included, and no “Replicate layout”.

    • The spatial pages use the same names: field sizes read “18 × 18”, with filler plots as “43 × 7 · 1 filler”; “Location to view” is “Location”; the sizes of each location are “Field dimensions, location 1”; and the options of “Plot order”, “Stack experiments” and “Blocks layout” are in sentence case (“Serpentine”, “By column”). Sizes are listed from the most square on, the one with fewer rows first of two alike; the size selected when a page opens is the same as before.

    • Calls without nrows and ncols return what they returned before.

    • Redesigned Welcome, Help and About pages, in one style: a green banner beside a photograph, NDSU green links with accessible contrast, and a shared footer. Welcome walks through choosing a design (each linked to its page), shows one example trial from map to field book, simulated response and R call, and has a section for teaching. Help gives every design its guide, reference page and offline help() command. About leads with the maintainer, gives every team member a card, and lists the package facts, how to cite FielDHub and the photo credits. The footer and Help now name Agricultural Data Analytics, NDSU (https://www.ndsu.edu/agricultural-data-analytics). The Welcome banner is an aerial photograph of a barley field trial at the Prosper Research Site, North Dakota, by Agricultural Data Analytics. dev/page_images.R renders the example’s images.

    • The app’s styles and scripts are served under a version that changes with their contents, so browsers load the current files after an update instead of a cached copy that no longer matches the pages.

    • Augmented RCBD, augmented row-column and RCBD-with-checks entry maps give each check its own colour from the same muted palette as the diagonal and optimized arrangements, so a check looks the same across designs. Blocks and replications keep their light backgrounds and white alleys; the plot-number maps do not highlight checks.

    • In the app, the “Select dimensions of field:” list of the augmented RCBD runs from the squarest field to the most elongated (5 x 6, 6 x 5, 3 x 10, 10 x 3, …), and the squarest field is selected by default. The API’s default field (nrows/ncols left out) is unchanged.

    • In both p-rep modules of the app, “Allow filler plots” and “Keep copies in distinct rows and columns” are now checked by default. The API defaults (allow_fillers = FALSE, rowcol_penalty = 0) are unchanged.

    • Single and multiple diagonal, sparse allocation and optimized arrangement field maps use the same style. Each check keeps its own colour, now from a muted palette, and the heavy check borders give way to a white grid around every plot. In a multiple diagonal the experiments are outlined in a mid-grey line so their start and end are clear; the experiment map also gives each experiment a muted background. Fillers are white with grey labels. Field books are unchanged.

    • p-rep and multi-location p-rep field maps use the same style: a white grid around every plot, replicated plots on a soft blue instead of the strong green, and filler plots white with grey labels. The plot-number map still highlights nothing. Field books are unchanged.

    • CRD, Latin square, Latin rectangle, factorial, split-plot and split-split-plot field maps use the same style. Every plot has a white grid line around it; RCBD-type reps and multiple Latin squares get a muted background each and white alleys; whole plots are outlined in grey and split-split-plot sub-plots in a lighter grey. Labels, titles and field books are unchanged.

    • RCBD, row-column and strip-plot field maps use the same style: one muted background per replication or block, white alleys between them, and a white line around every plot (for a strip-plot, the strips). RCBD checks share the neutral grey of the augmented designs. Alpha, square and rectangular lattices and incomplete block designs also get the plot grid, drawn as a ggplot2 layer until desplot can draw it. plot(x, field_grid = FALSE) removes the grid.

    • Augmented RCBD and augmented row-column field maps use the same style. Augmented RCBD blocks get a muted background each and are separated by white alleys, with a thin white line around every plot inside them. In both designs every check plot has the same neutral grey background instead of a colour per check, check numbers are dark instead of red, and filler plots are white with grey numbers. The augmented row-column entry map now shows entry numbers instead of treatment names, like the other entry maps, and both of its maps draw a white line around every plot so that neighbouring checks stay apart. Field books and plot numbers are unchanged.

    • Field maps of alpha, square and rectangular lattices and incomplete block designs use a field-plan style: each replication has a single muted background (the tints of the augmented RCBD blocks) and is separated from the next by a white alley, incomplete blocks are outlined in grey, and labels are dark. Entries are no longer coloured one by one, and the plot-number map now shows the incomplete blocks too. Each map is a single desplot call, so arguments passed through plot() (such as col.regions, cex or main) override any part of it (#72). Field books, plot numbers and coordinates are unchanged.

    • Augmented RCBD designs support optional block-based plot numbering with plotIncrement: for example, blocks start at 101, 201, 301 with an increment of 100. Additional experiment reps receive separate ranges within each location. The app exposes this through “Number plots by block”. Continuous numbering remains the default (#82).

    • Sparse and multi-location p-rep allocations (do_optim(), and through it sparse_allocation(), multi_location_prep() and both app pages) now use FielDHub’s own compiled block-design search instead of blocksdesign::blocks(). It reaches the same design efficiency in a fraction of the time: the median end-to-end run is about 24 times faster at 300 entries and over 100 times faster at 600, and a 2,000-entry allocation over six locations takes about one second and under 100 MB of memory, where blocksdesign needed 15 to 30 GB. Every allocation is now even: each entry has floor(copies_per_entry / l) or one more copies at each location. Designs of up to 632 plots get full swap passes, and square-lattice shapes (q^2 entries, q per location) start one search from the lattice. How the search ended is recorded in metadata$allocation_search. Installing FielDHub from source, including the app.R and dev/run_dev.R launchers, now needs a C++17 toolchain: Rtools on Windows and the Xcode command line tools on macOS.

    • Resolvable incomplete-block and lattice designs (incomplete_blocks(), alpha_lattice(), square_lattice() and rectangular_lattice()) and the column step of row_column(method = "twostage") are now built by the same compiled block search, in a resolvable mode that keeps every replicate complete, instead of blocksdesign::blocks(). Each run stops at a fixed amount of work, so it reproduces from its seed on the same platform and build. A 60-second time limit remains as a safeguard (on the reference machine the largest shapes searched reached the work limit in 8 to 13 seconds); a run stopped by it warns, and its result may not be reproducible from the seed. Two replicates of blocks of two are built in closed form.

    • Square and rectangular lattices that have an algebraic construction start from it and are A-optimal: their Level 2 A-efficiency reaches the A-Bound reported in blocksModel. Square lattices of order q use orthogonal Latin squares from the finite field GF(q) at prime-power orders (up to q + 1 replicates), products of such squares (MacNeish) at other orders, the 3m + 1 construction (orders 10, 22, 34, 46, …), pairs of orders 14, 18 and 26 found by FielDHub’s own computer search, and products of these (30, 42, 50, …); a design with r replicates needs r - 2 orthogonal squares. Rectangular lattices of s (s - 1) entries come from a square lattice of order s with one block deleted (Shrikhande’s method) and, with three replicates, from a Latin square of order s with a transversal deleted, so every s from 3 has a three-replicate construction. So a square lattice of order q with r replicates has a construction when r is at most m + 2, and a rectangular lattice of s (s - 1) entries when r is at most m + 1 or r is 3, where m is the number of orthogonal squares FielDHub builds at that order: q - 1 at a prime power; otherwise one less than the smallest prime-power factor of the order, raised to 2 where one of the constructions above gives a pair. Up to order 50, m is 1 at orders 6 (which has no orthogonal pair) and 38; 2 at 10, 12, 14, 15, 18, 21, 22, 24, 26, 30, 33, 34, 39, 42, 46, 48 and 50; 3 at 20, 28, 36 and 44; and 4 at 35, 40 and 45. A lattice with more replicates than that, such as square_lattice(t = 100, k = 10, reps = 5) or rectangular_lattice(t = 90, k = 9, reps = 4), has no construction: it is searched from random starts like any other incomplete-block design and is not guaranteed to reach the A-Bound.

    • row_column(method = "twostage") now improves the rows with the same block search, swapping two plots of the same column in different rows, so the column design is kept. For twostage, iterations is now an effort scale rather than a count of row-swap iterations: the row search’s budget is scaled by iterations / 1000, and the default 1000 is the full search. For onestage, iterations keeps its meaning.

    • The p-rep spreading optimizer (swap_pairs(), and the optimizer inside partially_replicated(), multi_location_prep() and optimized_arrangement()) is much faster, about 50 times on a 3,000-plot field. Its pair distances are built in one vectorized pass, and candidate swaps are scored from a coordinate index. Every layout is unchanged for the same seed.

    • New opt-in rule that keeps the copies of a replicated entry in distinct rows and columns: rowcol_penalty (default 0, off) and rowcol_scope in swap_pairs(), partially_replicated() and multi_location_prep(), and a “Keep copies in distinct rows and columns” box in both p-rep modules of the app. rowcol_penalty = Inf puts distinct rows and columns first, and the shared pairs left are reported in infoDesign$shared_pairs. With the default, every layout is unchanged.

    Onestage row-column designs and the A-Bound¶

    • row_column(method = "onestage"), with or without latinize, now runs on FielDHub’s own compiled block search instead of blocksdesign::design(). The search is staged: a first stage on the rows and columns, the repair of a singular joint model, and a joint row-by-column search. blocksdesign is no longer a dependency of FielDHub.
    • Seeded onestage layouts change. The designs are not less efficient: on a validation grid of 90,200 onestage designs per seed set (nested and latinized, two seed sets), every shape passed the non-inferiority checks against the previous blocksdesign designs, except the 23 rows below, and the paired timing shows the engine faster than design() on all 496 grid rows (shape by iterations; median time ratio 0.025, at most 0.13). The Phase 1 grids pass unchanged (300 of 300 and 132 of 132 shapes).
    • Seeded onestage layouts can also differ across platforms and BLAS libraries: designs of equal value are decided by tie rules on floating-point values.
    • Accepted losses. In 23 rows of the grid (18 distinct shapes, by iterations; 22 nested, 1 latinized; listed in tools/onestage-accepted-loss.csv in the source repository) the mean Column D-, Column A- or joint A-efficiency is below the previous mean by more than the margin, while the Row efficiency is equal and the joint D-efficiency is equal or higher. The largest shortfalls are 0.0069 (Column D) and 0.0169 (Column A), at 15 entries in 5 rows with four replicates and 20 iterations, and 0.0015 (joint A), at 20 entries in 10 rows with three replicates. The new search favors the joint D-optimal design, and the shortfall is the price of it.
    • Fewer fallbacks. In 1.6.0, 73 rows of the grid (41 distinct shapes, by iterations; 40 latinized, 33 nested; tools/onestage-fallback-changes.csv in the source repository) fell back to twostage for some seeds (1,204 of 14,450 seed runs). None of these shapes falls back now. Onestage is never replaced by twostage because of its size.
    • The fallback warning no longer mentions blocksdesign, and when a latinize = TRUE request returned a design that is not latinized it says so.
    • iterations sets the effort of the joint stage: the number of joint searches requested is max(1, round(10 * iterations / 200)) (10 at the default of 200). infoDesign$joint_searches reports the number requested and the number completed. The work of the search is capped (a fixed number of work units, not seconds), so on large designs the cap sets the number of joint searches. The shapes where this happens are listed in tools/onestage-truncation-list.csv in the source repository, which the maintainer reviewed and signed off on 2026-11-22.
    • One new warning, of class fieldhub_design_warning, for a joint stage that cannot start (beyond about 2,000 treatments, fewer with more than four replicates). The joint efficiency of an onestage design is computed from the treatment information.
    • The A-Bound numbers change. The new bound combines a convexity bound, a second-moment bound and a pair bound (tools/a-bound-report.csv in the source repository, 344 shapes of incomplete-block, alpha, square and rectangular lattice and row-column designs). It changed in 266 of the 344 shapes (lower in 180, higher in 86; the largest change is -0.0226 and +0.0661), it was never below the best A-efficiency found, and the best design reached it in 156 shapes, against 87 for the old bound.
    • Rectangular lattices with three or more replicates can show A slightly below the A-Bound, because the second-moment bound cannot reach every such lattice (see inst/PROVENANCE.md). For example, for 12 entries in blocks of 3 with three replicates, A is 0.6800618 and the bound is 0.6848249.
    • Acknowledgment. Earlier versions of FielDHub used the blocksdesign package (Edmondson 2021) to optimize block and row-column designs. FielDHub’s engine is an independent implementation, written without reading the blocksdesign source, and its designs were validated against those of blocksdesign as a black box: the 90,200 onestage designs above, and the Phase 1 grids. FielDHub is grateful to Rodney N. Edmondson for the package and for the optimized designs it gave FielDHub for years.

    Changes to results for a given seed¶

    The new allocation search changes the allocation, and so the field book, produced for a given seed by:

    • do_optim() with two or more locations;
    • sparse_allocation() and multi_location_prep() when they build the allocation themselves (two or more locations);
    • the Sparse Allocation and Multi-Location P-rep pages of the Shiny app.

    Field books built from an allocation passed in (sparse_list, optim_list) and one-location allocations are unchanged. A search stopped by its 60-second limit warns, and its result may not be reproducible from the seed on another machine.

    The resolvable block search changes the field book produced for a given seed by:

    • incomplete_blocks(), and the Incomplete Blocks Design (IBD) page;
    • alpha_lattice(), and the Alpha Lattice page;
    • square_lattice(), and the Square Lattice page;
    • rectangular_lattice(), and the Rectangular Lattice page;
    • row_column(method = "twostage"), both its columns and its rows, and the Resolvable Row-Column Design (RRCD) page when a small design falls back from onestage to twostage. The default method = "onestage" also changes (see “Onestage row-column designs and the A-Bound”).

    The designs are not less efficient than before, by a non-inferiority check against the previous results: over many seeds, the mean efficiency of a shape must not be lower than the previous mean, at 95% confidence, by more than half a standard deviation of the previous results. Every shape passed, with no exception accepted, on a validation grid of 300 incomplete-block, lattice and row-column shapes and on a separate grid of 132 shapes for the twostage rows. (Shapes of 1,000 entries or more were run on five seeds and checked on their worst seed only.) On the twostage grid, the mean Row A- and D-efficiency and the mean Column A-efficiency were never below the previous mean. The Row-by-Column efficiency is not what the twostage search optimizes, and its mean can be slightly lower: over two sets of seeds it was below the previous mean in 5 and 8 of the 132 shapes for A (by at most 0.0008) and in 12 and 10 for D, all within the margin. Square and rectangular lattices with a construction (see Enhancements) are A-optimal.

    The resolvable search has a limit. A design is searched only when it has at most 2,000 incomplete blocks in total (replicates times blocks per replicate) and the predicted work of its search fits within a fixed work cap; with blocks of four or more plots the cap is reached at roughly 3,700 to 4,500 entries with two replicates, 2,400 to 3,000 with three and 1,700 to 2,300 with four. A larger design is still returned, but unoptimized: a random connected resolvable design, with a warning of class fieldhub_design_warning. There are two exceptions, both returned without search or warning: a lattice with a construction, which is returned from the construction and is A-optimal, and two replicates of blocks of two, which are built in closed form at any size. The row search of row_column(method = "twostage") has a limit of the same kind (at most 2,000 rows in total, and a predicted work within the cap); above it the rows are left as the column design gave them, with a warning of the same class.

    Every other design is unchanged, apart from the onestage row-column designs and the A-Bound above.

    • Fixed the RCBD heatmap in the Shiny app, which decided whether simulated data existed by counting columns (ncol(df) == 8) and so went blank for any wider field book, and whose tooltip read an ENTRY column that the RCBD field book never had.

    • Fixed a bug in CRD() where, with treatments given as a character vector, every copy of a treatment was labeled with the same REP (all copies of the first treatment in REP 1, of the second in REP 2, and so on); each treatment now appears once in every replicate.

    • Fixed a bug in diagonal_arrangement() (kindExpt = "DBUDC", splitBy = "column") where, with ten or more blocks, the block labels were matched in alphabetical order (B1, B10, B2, …), so the entries of one block were placed in the region and under the name of another; with unequal block sizes the call failed with “Some entries are missing in the randomization!!”.

    • Fixed a bug in diagonal_arrangement() (kindExpt = "DBUDC") where, with unequal block sizes and experiment names not in alphabetical order (including the default Block1, …, Block10), the plot numbering paired sizes and names wrongly and failed with “missing value where TRUE/FALSE needed”.

    • Fixed a bug in diagonal_arrangement() (kindExpt = "DBUDC") where a block holding a single entry was filled with sample(entry), a permutation of 1:entry, giving the block the wrong entry.

    • Fixed two bugs in full_factorial(): with the RCBD type, locations sharing plot numbers (e.g. plotNumber = c(101, 101)) produced duplicated LOCATION/PLOT pairs, and level labels containing spaces (e.g. “Low N”) were split into two values. This also fixes the factorial page of the app for uploaded factor and level names with spaces (#43).

    • Fixed a bug in row_column() where every matrix in resolvableBlocks was filled with NA.

    • incomplete_blocks(), alpha_lattice(), square_lattice(), rectangular_lattice() and row_column() now keep the labels of a character t instead of replacing them with G-1, …, G-n, and CRD(), RCBD() and these functions reject duplicated treatment labels.

    • Fixed print(), summary() and plot() for several designs: print() returns the design invisibly, summary() shows the data input of partially_replicated() and optimized_arrangement() designs and now describes sparse_allocation() and multi_location_prep() designs, and plot() explains that split_families() results have no field layout.

    • When plotNumber or locationNames do not have one value per location, the design functions now raise a warning saying which defaults are used. Some replaced them silently, and RCBD(), RCBD_augmented() and optimized_arrangement() printed "Since plotNumber was missing" to the console even when plotNumber had been supplied.

    • Clearer errors for inputs that failed with unrelated messages: latin_square(t = 1), split_families() without l, and sparse_allocation() when no field dimensions fit. CRD() now accepts treatments given as a factor, and split_plot() and split_split_plot() accept a number of whole plots together with sub-plot labels.

    • Fixed a loop in the location balancing of sparse_allocation(), multi_location_prep() and do_optim() that had no lower bound and could run forever or add copies to the wrong entries; it now stops and warns when some locations cannot be balanced.

    • Fixed the simulated data of the Shiny app: under unequal replication (for example RCBD with repeated checks) a treatment’s responses mixed several distributions, the spatial simulation always used seed 0, and several modules discarded or never set the simulation seed. Simulated values for a given seed differ from earlier versions.

    • Fixed the Square Lattice and Optimized Arrangement modules of the Shiny app, which ignored the location names typed by the user.

    • Fixed the single diagonal and sparse allocation modules of the Shiny app, where changing the number of checks after randomizing redrew the entries without the seed, so the layout and the downloaded field book no longer matched the seed.

    • Uploading a file that cannot be read as CSV (e.g. ragged rows or an empty file) now shows an error message instead of ending the Shiny session.

    • Fixed crashes and silent failures in the Shiny app: the IBD module with a prime number of treatments, the strip-plot module with one replicate, and text such as "abc" in the starting plot or factor levels of the Latin square and factorial modules.

    • Fixed Shiny modules that watched or updated inputs that do not exist: the split-split-plot and strip-plot layout options did not refresh after changing the stacking, the p-rep, optimized arrangement and multi-location p-rep modules did not return to the first tab when switching the data source, and the multi-location p-rep module added a new observer on every run.

    • The heatmap tooltips of the Latin square, factorial, split-plot and strip-plot modules now show the treatment instead of an empty “Entry”, and the strip-plot heatmap follows the selected location.

    • The split-plot and split-split-plot modules now offer “Plot Order Layout” only for the CRD type: the layouts in complete blocks number their whole plots in a fixed order and did not use it.

    • Fixed the multiple diagonal module where, with “Repeat entries”, the entry names started at G3 whatever the number of checks, so NAME and ENTRY disagreed.

    • Fixed a bug in RCBD_augmented() where, with random = FALSE and filler plots, the first row of the field was overwritten with the fillers and a new set of all checks regardless of the blocks: a block spanning several rows ended up with two sets of checks (and some lines were left out of the field), and blocks sharing the first row lost most of theirs. Only the block holding the fillers now has its checks redrawn, so every block has each check once.

    • RCBD_augmented() now returns numeric ENTRY and CHECKS columns in every case. ENTRY was character for randomized designs without fillers, and CHECKS was character, with the string "NA" for filler plots, whenever the field had fillers; filler plots now have CHECKS = NA.

    • Fixed a bug in diagonal_arrangement() and sparse_allocation() where, with a cartesian planter, an even number of rows and filler plots, the experiment names placed the fillers at the wrong end of the first row: one check and one entry in each location got EXPT = "Filler" and PLOT = 0, while the real filler plots got plot numbers. The randomization itself is unchanged.

    • The single diagonal, multiple diagonal and sparse allocation modules of the Shiny app now build their designs with diagonal_arrangement() and sparse_allocation(), so the app and R give the same design for the same inputs and seed. The modules used to re-implement the randomization and drew the random numbers in a different order, so the same seed gave a different design in the app. As a result, designs made in the app with a given seed differ from earlier versions, generated entries are named as in R, field-book IDs restart at 1 in each location, filler plots of sparse allocations have EXPT = "Filler", and uploaded check entries must be consecutive numbers.

    • Fixed optimized_arrangement() drawing the replication of the checks before setting the seed when amountChecks is not a multiple of the number of checks, so the same seed could give different designs.

    • The documentation of swap_pairs(), do_optim(), sparse_allocation() and multi_location_prep() now matches their defaults and the elements they return.

    • split_plot(), split_split_plot() and strip_plot() now raise a classed input error for a sub-plot, sub-sub-plot or strip factor with only one level, which used to crash with base R’s “incorrect number of dimensions”; a single whole plot and a single replicate are still valid designs. incomplete_blocks() and row_column() (and, through them, alpha_lattice(), square_lattice() and rectangular_lattice()) now explain that there is not enough replication for the block size instead of leaking blocksdesign’s “Too many parameters for the available plots”. full_factorial() no longer names RCBD() in the error it raises for a single-run design (every factor at one level). plot() of an unavailable location, stacking or layout option now raises a classed fieldhub_input_error that lists the valid options, replacing the internal field-layout adapter’s warn-and-return-NULL path (and its short-lived fieldhub_layout_warning class); the augmented RCBD app module routes the same error through the app’s validation messages instead of silently swallowing it.

    • RCBD_augmented()’s “the field dimensions do not fit” error, raised when explicit nrows/ncols do not fit the requested blocks, now lists the same accepted block counts as its “the number of blocks is too small” error; it previously searched from 5 blocks instead of 3, so its list silently left out the smaller, still-accepted block counts of 3 and 4. row_column()’s error for an infeasible nrows no longer names incomplete_blocks(); both it and incomplete_blocks() now validate their block size the same way and list every accepted size.

    • Clearing or otherwise invalidating a “# of Locations”, “# of Checks” or “Checks per Block” input no longer ends the Shiny session in the Diagonal, Multi-location Diagonal, Optimized Arrangement, p-rep, Multi-location p-rep, Sparse Allocation and Augmented RCBD modules, including on the Augmented RCBD upload path and after uploading data in Diagonal and Multi-location p-rep. These observers, and the reactives they read (a malformed upload among them), built their location-view/replicate/dimension choices straight from the raw input or an unguarded comparison, any of which can throw on Shiny’s NA for a blank input; an uncaught error inside an observer ends the whole session. They now validate the count with a plain helper first and route a failure through the app’s existing validation-message mechanism. A selector fed an invalid count (such as “view location” or “# of Checks”) keeps showing its last valid choices, with no inline message of its own; the design’s own table or field book still shows the usual validation message once it is built from invalid input.

    • Text in the p-rep “# of Entries Per Rep Group” or “# of Rep Per Group” inputs, such as “75,abc”, is now explained by name instead of failing with a raw R error from 1:sum(NA), and partially_replicated() itself now rejects a missing or fractional repGens/repUnits value with a classed input error. Any error the app does not expect (one that is not a FielDHub condition, so a bug rather than a problem with the input) no longer ends the Shiny session when it happens inside an observer, for example a missing value reaching the diagonal check-percentage or augmented-RCBD block choices. It is always logged to the R console as “FielDHub: unexpected problem …”, and shown to the user as “Unexpected problem: ”: where the output would be for an output, and in a dialog for an observer that updates a selector (which has no output to show it in).

    Changes to results for a given seed:¶

    Some of the fixes above change the design produced for a given seed. Field books generated with FielDHub 1.5.0 or earlier should be checked if they came from:

    • CRD() with treatments given as a character vector (wrong REP labels).
    • diagonal_arrangement() with kindExpt = "DBUDC" and splitBy = "column" with ten or more blocks (entries under the wrong experiment).
    • full_factorial() of the RCBD type with plot numbers shared or overlapping across locations, or with level labels containing spaces.
    • incomplete_blocks(), alpha_lattice(), square_lattice(), rectangular_lattice() or row_column() with a character t (the labels were replaced by G-1, …, G-n; the randomization itself is unchanged).
    • row_column() without an explicit method (its new default, method = "onestage", jointly optimizes rows and columns; see New features). Pass method = "twostage" to reproduce field books generated by 1.5.x and earlier, which always used the two-step optimization.
    • The Square Lattice and Optimized Arrangement modules of the Shiny app with more than one location (the location names were ignored).
    • The single diagonal or sparse allocation modules of the Shiny app when the number of checks was changed after randomizing.
    • diagonal_arrangement() or sparse_allocation() with planter = "cartesian", an even number of rows and filler plots (one check and one entry per location labeled as fillers).
    • RCBD_augmented() with random = FALSE when the field has filler plots (blocks with too many or too few checks, and possibly missing lines).
    • Not a design change: RCBD_augmented()’s ENTRY and CHECKS columns are now numeric in every case instead of character (see Fix bugs); values are unchanged and match as.numeric() of the 1.5.0 columns.
    • optimized_arrangement() when amountChecks is not a multiple of the number of checks (the design was not reproducible).
    • The Split-Split Plot module of the Shiny app with the horizontal reps layout (the exported field book had the vertical layout).
    • Not a design change: the golden layout-preview snapshot for stacked = "grid_panel" on a design that does not support it now shows the classed fieldhub_input_error message instead of the placeholder “No layout”, because plot()/plot_layout() now raise that error instead of returning NULL (see Fix bugs). No generated field book is affected.
    • Not a design change: do_optim() results now carry an additional fieldhub_sparse_optimization or fieldhub_multi_prep_optimization class next to the legacy Sparse/MultiPrep one, so callers can recognize a FielDHub allocation plan without matching on the legacy name. The legacy classes, print()/summary() behavior and generated allocations are unchanged.
    • Not a design change: optimized_arrangement() results now record their check replication as rep_checks in metadata$parameters instead of amountChecks, whichever argument name the call used. reproduce_design() still replays older results recorded with amountChecks. The field book, infoDesign and every other output are unchanged.

    Standalone Functions¶

    • Created the do_optim() function. This function generates the sparse or p-rep allocation to multiple locations. It optimized the allocation by using incomplete blocks.

    • Created the sparse_allocation() function. This new function uses the other function, do_optim(), to generate the sparse allocation, then uses the function diagonal_arrangement() to create unreplicated designs across multiple locations.

    • Created the multi_location_prep() function. It uses within the optimization function do_optim() to generate the partially replicated (p-rep) allocation, then uses the function partially_replicated() to create the p-rep designs across multiple locations.

    • Created the pairs_distance() function. This function calculates pairwise distances between all elements in a matrix that appears twice or more.

    • Created the swap_pairs() function. It swaps pairs in a matrix of integers and optimizes the p-rep design. This function modifies the input matrix \(X\) to ensure that the distance between any two occurrences of the same integer is at least a distance \(d\), by swapping one of the occurrences with a random occurrence of a different integer that is at least \(d\) away. The function starts with starting dist at \(d = 3\) and increases it by \(1\) until the algorithm no longer converges or the max number of iterations have been performed.

    • Created the search_matrix_values() function. It looks for values that appear in the same row in a matrix and return the row number, value, and frequency.

    • Added optimization process for the partially replicated (p-rep) designs. It uses the function swap_pairs().

    • Added vignettes and help documentation for all the new functions.
